# 开发日志编写指南

开发日志条目按日期组织，每天一个文件。

## 目的

每日日志记录简短的日期化笔记，包括：

- 添加或更新了哪些文档
- 做出了什么设计决策
- 下一步计划做什么工作
- 日后有用但不属于正式架构文档的小背景信息

## 规则

- **每天一个文件** - 同一天的所有工作归入同一个文件
- **追加新条目** - 在文件顶部添加新的 `### YYYY-MM-DD` 章节（倒序时间）
- **保持条目简短** - 优先使用项目符号，链接到主文档或代码路径
- **非权威来源** - 这是轻量级的上下文，不是规范性的架构
- **链接到真实文档** - 引用设计决策时，链接到架构文档或代码路径
- **将日志文件视为仅追加的历史** - 文件长度本身不是缺陷；不要因为日常日志超出活跃文档大小指南就将其标记

## 路径约定

- `docs/logs/{year}/{month}-{day}.md`
