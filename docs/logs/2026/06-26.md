#### 信号选择偏向 SOL bug 修复 — 13:20

**问题：**
- 实盘总是选择 SOL-USDT-SWAP 开仓，即使其他 symbol 也有有效信号
- 每轮都尝试为 SOL 挂载 SL/TP 订单，交易所返回 400 Bad Request

**根因：**
1. `beta_decouple.compute_signals` 遍历所有历史 bar（96 根），为每个满足条件的 bar 都生成信号
2. SOL 排在 `OKX_INST_IDS` 第一个，历史信号最多
3. `ensemble.resolve_conflicts` 按 `entry_ts` 分组时，SOL 的信号总是被优先选中

**修复：**
1. `beta_decouple.py`：从最新 bar 向前遍历，找到第一个满足条件的 bar 后立即 break
2. `pipeline.py`：添加 `_compute_signal_score` 函数，从 z-score、止损距离、R:R 三维度评分
3. 信号按 score 降序排序后再进入 ensemble 选择
4. `run_live_echo.py`：移除 `run_once` 中每轮调用 `attach_sltp_to_existing` 的逻辑，SL/TP 只在开仓时通过 `attachAlgoOrds` 一起挂
5. `place_market_order` 改为接收策略信号的 `stop_price` / `target_price`，不再使用固定金额

**缺陷记录：**
- `docs/bugs/2026-06-26-signal-selection-bias.md`

#### 代理 SSL 问题修复 — 12:35

**问题：**
- `run_live_echo.py` 报错 `ConnectError: [SSL: UNEXPECTED_EOF_WHILE_READING]`
- 所有 HTTPS 请求通过代理失败

**诊断：**
- 测试不同代理协议：`socks5://`、`socks5h://`、`http://`
- 测试不同端口：34982（SOCKS5）、7890（HTTP）、7897（混合）
- 发现：代理 HTTP 正常，HTTPS 失败

**根因：**
- FlyingBird-Lite 代理软件 HTTPS TLS 处理异常
- 切回 Clash Verge 后问题解决

**修复：**
- 默认代理改回 `socks5h://127.0.0.1:34982`
- 清理 `src/okx_sdk.py` 中无用的重试代码
- 更新 `docs/architecture/sys-proxy-rules.md` 代理配置表

**验证：**
- `run_live_echo.py --once` 测试成功
- 所有 OKX API 请求返回 `HTTP/2 200 OK`
- 成功下单 SOL-USDT-SWAP 空单

**教训：**
- 代理软件 HTTPS 支持不稳定时，优先切换代理软件而非调整代码
- SOCKS5 协议在传输层统一处理 HTTP/HTTPS，避免 CONNECT 隧道问题
