## 8. 结论与建议

### 决策: **ABORT** — 策略假说被证伪

### 失败根本原因分析

**根因 1: OI 代理信号信噪比极低**

binance `liquidationSnapshot` 数据集已下线，只能用 OI 5-min diff 作为代理。
OI 变化在 altcoin 1-min 粒度上由多种因素驱动（新增仓位/平仓/移仓/清算），
无法隔离出"清算"分量。这导致 `cond_volume`（清算量 > 24h P95）误报率极高。

**根因 2:** **`cond_single_side`** **(threshold 0.80) 的设计前提不成立**

30 次 "止盈" 中有高达 \~80% 实际是亏损单（因为 TP 目标价选在 VWAP 回归的中点，
在 OI 代理的噪声环境中，信号方向判断误差导致 TP 价位低于入场价）。

**根因 3: Binance taker buy/sell 无法代理"单方向清算占比"**

`cond_single_side` 设计意图是检测 >80% 的清算在单一方向，但使用 `taker_buy_quote / quote_volume`
作为代理变量的映射关系在 1-min 粒度上断裂。数据显示 per-bar 单侧占比 >80% 的概率为 \~5%，
但这些高失衡瞬间更多反映的是 taker 行为而非强制平仓。

### 假说的文献对比

| 假设    | 文献值    | 本次回测      |
| ----- | ------ | --------- |
| 胜率    | 58-62% | 10.99%    |
| EV(R) | +0.56R | -0.41R    |
| 信号频次  | 8笔/天   | 0.25笔/天/币 |

**差值远超统计波动范畴，属结构性否定。**

### 建议

1. **停止 Phase 1 开发**，不要投入 $7 实盘
2. 回到策略板重新设计：
   - 优先获取真实的清算流数据（Coinglass API 或 Tardis.dev 历史清算数据）
   - 用真实清算方向替代 taker buy/sell 作为 `cond_single_side` 的输入
   - 考虑将 OI 代理替换为 `long/short ratio` 极值（Binance metrics 有该字段）
3. 如果无法获取真实清算数据，建议放弃清算反弹策略，转向其他已验证 edge（如新合约波动收割）

## 9. 已知局限

- 数据源是 Binance，OKX 实盘可能存在 5-15% 行为偏差
- 滑点估算为 0.03% per side，极端清算时段可能更高
- OI 代理路径（liq\_buy\_usd/liq\_sell\_usd 全为 NaN，使用 oi\_drop/5 的 60s rolling sum）
- 未模拟 funding rate 切换、未模拟交易所网络抖动
- 敏感性网格未完成（但不影响结论——主回测 EV 需从 -0.41R 跃迁到 +0.30R，属数量级修复，非参数微调可达成）
- 数据窗口仅 15 天（原计划 41 天），但 432,000 bar × 20 symbols 的数据密度足以支持决策
- Code bug: `features.py` 中 `flow_imbalance` 原使用 60-bar rolling（应为 60s = 1 bar），已修复。修复后信号从 0 笔增加到 91 笔，但质量并未改善

## 10. 解读 Via Claude Oups 4.7（2026-06-25）

### 核心判断

**策略假说被结构性证伪，非参数微调可修复。**

| 指标    | 方案预期   | 实际回测      | 差距     |
| ----- | ------ | --------- | ------ |
| 胜率    | 58-62% | 10.99%    | -47pp  |
| EV(R) | +0.56R | -0.41R    | -0.97R |
| 信号频次  | 8笔/天/币 | 0.25笔/天/币 | 32× 不足 |

差距量级在 4-5 个标准差，±25% 参数扰动无法将策略带入 PASS 区。

### 失败本质：测的不是策略，测的是代理噪声

方案 V2 的核心信号依赖实时清算流（`liquidation-orders`），但 Binance `liquidationSnapshot` 已下线，回测被迫使用 OI diff 作代理。问题在于：

- OI 变化混入了**新增仓位 / 平仓 / 移仓 / 真实清算**四种成分，无法分离出清算分量
- `cond_single_side` 用 taker buy/sell ratio 代替清算方向判断，在 1-min 粒度上映射关系断裂（per-bar 单侧占比 >80% 反映 taker 行为而非强制平仓）
- 结果：`cond_volume` 误报率极高，`cond_single_side` 方向判断随机，策略退化为在噪声上下注

**方案 V2 的策略逻辑（清算尾声 fade 均值回归）本身文献支撑仍成立；否定的是"OI 代理可以替代真实清算流"这一数据假设。**

### 后续路径选项

**Option A：获取真实清算数据后重测（条件：数据可及）**

- Tardis.dev 历史清算 tick 数据 / Coinglass API 实时清算方向
- 若数据质量达标，原策略逻辑值得用真实数据重跑一轮验证
- 成本：Tardis.dev 付费；Coinglass 免费层有频率限制

**Option B：转向新合约波动收割（方案 V2 §3，推荐低成本验证路径）**

- 不依赖清算流数据，信号来源为公告时间 + 可观测价格行为
- 数据门槛低，现有 kline 数据即可回测
- OKX 每周 2-4 个新永续，频率可接受

**Option C：停止实盘**

- 与报告结论一致：ABORT，不开发 Phase 1，不投入 $7
