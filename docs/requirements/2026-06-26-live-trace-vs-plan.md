# 特性：实盘追踪与计划对比（Live Trace vs Plan）

## 目的

让 AI agent 扮演"量化算法专家"和"算法交易专家"角色，自动追踪实盘运行效果，对比计划与实际的偏差，回答三个核心问题：

1. **代码执行正确性** — 实盘代码是否按照设计方案正确执行？是否存在逻辑偏差、参数传递错误、或时序问题？
2. **效果符合预期** — 实盘跑出来的效果，是否真的与计划中的预期一致？如果存在偏差，偏差来源是什么？
3. **信号漏斗透明度** — 为什么一直开不出单子？是真的被算法正确过滤掉了，还是算法实现有 bug 导致信号丢失？

核心关切：
- 方案设计优秀，但实盘表现不理想——AI agent 负责发现、归因、并提出纠正建议，用户只看结论。
- 长时间无交易时，用户需要知道是"市场没给机会"还是"代码坏了"。

## 范围内

### AI Agent 角色定义

| 角色 | 职责 | 触发时机 |
| --- | --- | --- |
| **量化算法专家 Agent** | 审查信号一致性、盈亏偏差、策略表现归因、信号漏斗分析 | 每笔交易完成后、周期性汇总时、无交易超时时 |
| **算法交易专家 Agent** | 审查执行偏差、滑点分析、风控触发一致性 | 每笔交易完成后、异常告警时 |

### Agent 追踪维度

#### 交易执行维度（有交易时）

| 维度 | 说明 | 数据来源 |
| --- | --- | --- |
| **信号一致性** | 实盘触发的信号是否与回测/纸交易信号一致 | `state.json`、OKX 成交记录 |
| **执行价格偏差** | 实盘成交价 vs 信号 close 价的滑点 | OKX `fill_price` vs `signal.close` |
| **持仓时长偏差** | 实盘持仓时间 vs 策略预期持仓时间 | 开仓/平仓时间戳 |
| **盈亏偏差** | 实盘 PnL vs 回测预期 PnL | OKX 账户权益变化 |
| **风控触发一致性** | RiskGuard 触发条件是否与设计一致 | `RiskGuard` 日志 |
| **资金利用率** | 实际使用资金 vs 计划使用资金 | OKX 余额 vs `risk_pct` 计算值 |

#### 信号漏斗维度（无交易时）

| 维度 | 说明 | 数据来源 |
| --- | --- | --- |
| **原始信号数量** | 策略因子产生了多少原始信号 | 因子计算日志 |
| **过滤信号数量** | 有多少信号被过滤，过滤原因分布 | `compute_ensemble_signals()` 日志 |
| **过滤原因分类** | 风控过滤 / 重复信号过滤 / 其他过滤 | 日志分类统计 |
| **预期 vs 实际信号频率** | 回测中该时段应有多少信号 vs 实际产生多少 | 回测计划 vs 实际日志 |
| **数据完整性** | 原始 K 线数据是否有缺失或异常 | 数据源日志 |
| **代码执行路径** | 代码是否走到了信号生成的分支 | 代码埋点日志 |

### Agent 工作流程

#### 流程 A：有交易时（事后复盘）

```
实盘脚本完成一笔交易
    │
    ├─> [系统] 自动生成交易快照
    │     - 信号详情（symbol, side, entry_price, stop, target）
    │     - 执行详情（fill_price, fill_time, slippage）
    │     - 结果详情（pnl, hold_duration, exit_reason）
    │
    ├─> [量化算法专家 Agent] 自动加载回测/纸交易计划
    │     - 对比信号一致性
    │     - 计算盈亏偏差
    │     - 判断是否符合策略预期
    │
    ├─> [算法交易专家 Agent] 审查执行质量
    │     - 计算滑点
    │     - 分析执行延迟
    │     - 验证风控触发正确性
    │
    ├─> [Agent 协作] 生成综合分析结论
    │     - 偏差是否在可接受范围
    │     - 异常归因（代码问题 / 市场滑点 / 参数漂移 / 时序差异）
    │     - 是否需要人工介入
    │
    └─> [系统] 输出报告给用户
          - 正常：简要摘要
          - 异常：详细分析 + 纠正建议
```

#### 流程 B：无交易时（信号漏斗分析）

```
定时检测（每小时 / 每日）
    │
    ├─> [系统] 检查是否有新交易
    │     ├─> 有交易 → 走流程 A
    │     └─> 无交易 → 继续流程 B
    │
    ├─> [量化算法专家 Agent] 分析信号漏斗
    │     ├─> 检查原始信号
    │     │     - 因子是否产生了信号？
    │     │     - 数据是否完整？
    │     │     - 代码是否执行到了信号生成分支？
    │     │
    │     ├─> 检查过滤环节
    │     │     - 信号被过滤了吗？
    │     │     - 被哪个环节过滤？（风控 / 重复 / 其他）
    │     │     - 过滤原因是否合理？
    │     │
    │     └─> 对比预期
    │           - 回测中该时段应有多少信号？
    │           - 实际产生多少？
    │           - 差异是市场原因还是代码原因？
    │
    ├─> [Agent] 生成漏斗分析结论
    │     ├─> 结论 1：市场没给机会（正常）
    │     │     - "过去 4 小时无信号，回测同期也无信号，属正常波动"
    │     │
    │     ├─> 结论 2：信号被正确过滤（正常）
    │     │     - "产生 3 个信号，均被风控过滤（已持仓 / 超限），符合预期"
    │     │
    │     ├─> 结论 3：信号频率低于预期（需关注）
    │     │     - "回测同期应有 5 个信号，实际 0 个，差异显著"
    │     │     - "建议：检查数据完整性、因子计算逻辑"
    │     │
    │     └─> 结论 4：疑似代码问题（需立即介入）
    │           - "代码未进入信号生成分支，疑似条件判断错误"
    │           - "建议：检查 xxx 代码路径"
    │
    └─> [系统] 输出报告给用户
          - 正常：简要摘要
          - 异常：详细分析 + 纠正建议
```

### 产出物

| 产出物 | 内容 | 接收者 | 触发条件 |
| --- | --- | --- | --- |
| **单笔交易报告** | 交易快照 + 偏差分析 + 结论 | 用户（简要） | 每笔交易完成后 |
| **信号漏斗报告** | 信号统计 + 过滤原因 + 频率对比 | 用户（简要/详细） | 无交易超时时 |
| **周期性汇总报告** | 统计指标 + 趋势分析 + 异常标注 | 用户（详细） | 每日/每周 |
| **异常告警** | 偏差超阈值 + 归因 + 纠正建议 | 用户（立即） | 实时 |
| **纠正建议** | 具体可执行的修复方案 | 用户（决策用） | 异常时 |

## 范围外

- 策略因子本身的逻辑修改或优化（Agent 只追踪，不修改策略）
- 回测引擎的重新运行或参数调优
- OKX 账户的资金管理或出入金
- 多账户并行追踪（当前仅支持单账户）
- 实时流式监控（当前为交易结束后批量分析）
- 滑点优化或执行算法改进（Agent 只测量，不优化执行）
- Agent 自动修复代码（只提建议，不自动改代码）

## 用户交互流程

### 正常情况（有交易，无异常）

```
用户
  │
  ├─> 查看每日汇总报告
  │     - "今日 5 笔交易，偏差均在可接受范围"
  │     - "平均滑点 0.03%，盈亏偏差 -2.1%"
  │
  └─> 无需操作，继续运行
```

### 正常情况（无交易，市场原因）

```
用户
  │
  ├─> 查看信号漏斗报告
  │     - "过去 6 小时无交易"
  │     - "回测同期也无信号，属正常波动"
  │     - "建议：继续观察"
  │
  └─> 无需操作，继续运行
```

### 异常情况（有交易，偏差超阈值）

```
用户
  │
  ├─> 收到异常告警
  │     - "⚠️ BTC-USDT 多头信号执行偏差超阈值"
  │     - "滑点 0.8%（阈值 0.5%），疑似流动性不足"
  │     - "建议：调整该 symbol 的滑点预期或减小仓位"
  │
  ├─> 审查 Agent 建议
  │
  └─> 决策
        - 采纳建议 → 手动调整参数
        - 忽略偏差 → 记录为已知差异
        - 深入调查 → 调取详细日志
```

### 异常情况（无交易，疑似代码问题）

```
用户
  │
  ├─> 收到异常告警
  │     - "⚠️ 过去 12 小时无交易，回测同期应有 8 个信号"
  │     - "原始信号 0 个，代码未进入因子计算分支"
  │     - "疑似原因：数据源返回空数据，因子提前 return"
  │     - "建议：检查数据源连接和数据完整性校验逻辑"
  │
  ├─> 审查 Agent 建议
  │
  └─> 决策
        - 立即检查 → 查看日志，修复代码
        - 继续观察 → 记录时间点，看是否持续
        - 重启脚本 → 尝试恢复
```

## 业务规则

### 快照规则

- 每笔交易完成后必须生成快照，不得遗漏
- 快照必须包含完整的信号、执行、结果三段信息
- 快照一旦生成不得修改，只可追加 Agent 注释

### 偏差阈值（Agent 判断标准）

#### 交易执行偏差阈值

| 指标 | 正常范围 | 需关注 | 需立即介入 |
| --- | --- | --- | --- |
| 价格滑点 | ≤ 0.1% | 0.1% ~ 0.5% | > 0.5% |
| 盈亏偏差 | ≤ 10% | 10% ~ 30% | > 30% |
| 持仓时长偏差 | ≤ 20% | 20% ~ 50% | > 50% |
| 胜率偏差（10笔滚动） | ≤ 10% | 10% ~ 20% | > 20% |

#### 信号漏斗阈值

| 指标 | 正常范围 | 需关注 | 需立即介入 |
| --- | --- | --- | --- |
| 无交易持续时间 | ≤ 4 小时 | 4 ~ 12 小时 | > 12 小时 |
| 信号频率偏差（vs 回测） | ≤ 20% | 20% ~ 50% | > 50% |
| 信号过滤率 | ≤ 50% | 50% ~ 80% | > 80% |
| 数据缺失率 | 0% | > 0% 且 < 5% | ≥ 5% |

### Agent 行为规则

- Agent 不得自动修改实盘代码或参数
- Agent 不得自动停止实盘运行（除非触发 RiskGuard）
- Agent 结论必须附带数据支撑，不得凭空推测
- Agent 对同一问题的重复告警需合并，避免告警风暴
- Agent 归因不确定时，必须列出所有可能原因

### 报告规则

- 正常情况：简要摘要（1-2 行）
- 需关注情况：详细分析 + 建议（1 段）
- 需立即介入：完整分析 + 纠正建议 + 紧急程度标注

### 数据保留

- 交易快照永久保留
- Agent 分析报告保留 90 天
- 告警记录保留 180 天

## 角色与权限

| 角色 | 职责 | 权限 |
| --- | --- | --- |
| **量化算法专家 Agent** | 信号一致性审查、盈亏偏差分析、策略表现归因、信号漏斗分析 | 读取快照、读取计划、读取信号日志、输出报告 |
| **算法交易专家 Agent** | 执行偏差审查、滑点分析、风控验证 | 读取快照、读取日志、输出报告 |
| **用户** | 审查报告、决策是否调整 | 查看报告、修改参数、停止运行 |

### 权限边界

- Agent：只读 + 分析 + 报告
- 用户：读写 + 决策 + 执行

## 边缘情况

### 交易执行相关

- **交易中途脚本崩溃** — 快照可能不完整，Agent 需标记为"部分快照"并说明影响
- **OKX API 返回延迟** — 成交记录可能滞后到达，Agent 需等待确认后再分析
- **同一 symbol 连续交易** — 快照需正确关联到对应的信号，Agent 需验证关联正确性
- **部分成交** — 一笔信号对应多笔小额成交，Agent 需合并计算后再分析
- **计划中无对应信号** — 实盘触发了回测中未出现的信号，Agent 需单独标注为"计划外信号"
- **资金变动干扰** — 运行期间账户被外部充值/提现，Agent 需识别并排除干扰

### 信号漏斗相关

- **数据源断连** — K 线数据中断，因子无法计算，Agent 需识别是数据问题还是代码问题
- **信号延迟到达** — 因子计算耗时过长，信号产生时行情已变化
- **过滤规则误伤** — 风控规则过于严格，过滤了本应执行的信号
- **回测基准不一致** — 回测用的数据/参数与实盘不同，导致预期信号数量不准
- **代码分支未覆盖** — 某些市场条件未在代码中处理，导致信号生成逻辑被跳过
- **并发信号冲突** — 多个 symbol 同时产生信号，但资金只能支持部分执行

### Agent 判断相关

- **Agent 自身判断不确定** — 必须明确标注不确定性，给出多个可能原因
- **回测数据缺失** — 无法对比预期信号数量时，Agent 需说明并建议获取回测数据
- **多策略信号重叠** — 多个策略同时运行时，信号归属判断可能混淆

## 未解决问题

### 通用问题

- **快照存储格式** — 当前计划使用 JSON 文件，是否需要引入数据库？
- **Agent 实现方式** — 使用 LLM prompt 还是规则引擎？还是混合？
- **多策略并行追踪** — 如果同时运行多个策略，快照和 Agent 分析如何隔离？
- **回测基准版本管理** — 回测计划更新后，历史快照是否需要重新对比？
- **告警通知渠道** — 当前仅输出到日志，是否需要接入消息通知（如 Telegram）？
- **Agent 调用频率** — 每笔交易触发 vs 定时批量触发？

### 信号漏斗相关

- **信号埋点位置** — 在代码哪个位置记录原始信号、过滤信号、最终信号？
- **回测基准获取** — 如何自动获取"该时段应回测产生多少信号"的数据？
- **过滤原因标准化** — 过滤原因如何分类和记录，便于 Agent 统计分析？
- **无交易检测频率** — 多长时间检测一次"是否无交易"？1小时？4小时？每日？
- **信号漏斗报告格式** — 如何清晰展示信号从产生到执行的完整漏斗？

## 验收准则

### 交易执行追踪

- [ ] 每笔实盘交易完成后自动生成交易快照
- [ ] Agent 能自动读取快照并进行偏差分析
- [ ] Agent 分析结论包含数据支撑和归因说明
- [ ] 正常情况输出简要摘要，异常情况输出详细分析
- [ ] 偏差超阈值时 Agent 能触发告警
- [ ] Agent 不会自动修改代码或停止运行
- [ ] 追踪机制不影响实盘脚本的正常运行性能（延迟 < 100ms）
- [ ] 至少完成一轮完整的"快照 → Agent 分析 → 报告 → 用户决策"闭环验证

### 信号漏斗追踪

- [ ] 代码中已埋点记录原始信号、过滤信号、最终信号
- [ ] 无交易超过阈值时间时，Agent 自动触发信号漏斗分析
- [ ] Agent 能区分"市场无机会"和"代码有问题"两种情况
- [ ] 信号漏斗报告清晰展示信号从产生到执行的完整链路
- [ ] Agent 对"疑似代码问题"的判断有具体数据支撑
- [ ] 信号频率偏差超阈值时能触发告警
- [ ] 至少完成一轮完整的"无交易 → 漏斗分析 → 归因 → 用户决策"闭环验证
