# 需求合成指南

## 目标

本指南用于将原始输入转化为可直接进入实施阶段的需求。

## 输入来源

- `docs/input/` 原始材料
- `docs/discussions/` 澄清说明纪要
- 现有的 `docs/design/` 与 `docs/architecture/` 负责文档

## 输出要求

一份需求文件应当清晰表述：

- 目的
- 范围
- 不包含的内容（非目标）
- 核心用户流程
- 业务规则
- 权限或角色影响
- 已知的边缘情况
- 未解决的问题
- 验收准则

## 规则

禁止用流畅的措辞掩盖未解决的歧义。必须将歧义明确记录。

## 实施就绪门禁

只有当以下条件全部满足时，一份需求才被视为"实施就绪"：

- [ ] 范围内的行为已足够具体，开发人员无需猜测即可构建用户可见行为
- [ ] 非目标被明确列出
- [ ] 已描述主要用户流程
- [ ] 角色与权限已被覆盖，或明确标注不适用
- [ ] 数据/模型影响已被覆盖，或明确标注不适用
- [ ] API/集成影响已被覆盖，或明确标注不适用
- [ ] 空态、加载态、错误态与权限拒绝态在用户可见处已被覆盖
- [ ] 验收准则具备可测试性
- [ ] 开放性问题要么不阻断实施，要么已明确标注会阻断实施

若某个开放性问题会改变用户可见行为、数据/模型形态、API 行为、认证/权限行为或外部集成行为，则暂停并请求澄清。

## 最小需求骨架

```md
## 目的

## 范围内

## 范围外

## 边缘情况

## 未解决问题

## 验收准则
```
