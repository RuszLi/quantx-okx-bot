# 项目愿景

## 用途

说明 `okx-bot` 长期的产品与工程吸引子。

## 产品目标

- 搭建一个文件可审计的 OKX 加密货币算法交易工作区，使策略研究、回测验证、门控后的实盘执行、诊断、修复与重启都在仓库内及 `runtime/` 目录下留下可持久追溯的证据。

## 主要用户

- 智能体操作员：负责运行策略研究与实盘循环。
- 人工审核员：审计策略变更、风险边界与运行时证据。
- 策略负责人：维护具体策略线（如 `fair_value_discount`）。

## 必须保持成立的约束

- 实盘执行必须经过门控；不允许默认绕过门控与阶段策略链路。
- 仓库文档是受支持行为与执行边界的唯一权威来源。
- 运行时状态以文件形式承载，除非后续归属文档明确变更该基线。
- 历史实验证据可用于解释决策，但不能悄悄演变为受支持的稳定规则集。
- 在可执行假设天然具备多因子或耦合特征时，研究与治理不得强行要求 `单变量唯一` 的策略搜索或晋级逻辑。
- 短暂的重启窗口、近期少量市场窗口、或 1-2 个真实资金样本可触发复盘审查，但本身不足以直接选定、下架或冻结策略参数或因子。

## 明确的非目标

- 通用多策略交易平台。
- 精致的终端用户 Web 产品或以面板为先的控制平面。
- 在没有新归属文档支撑的情况下，自动扩展到新交易所、新资产类别或新风险模型。

## 首个生产里程碑的成功标准

- 目标策略线已具备稳定的需求、设计与架构文档，且与受支持循环一致。
- 操作员能够通过已提交的命令与运行时文件，完整跑通主循环、查看状态并解读重启/修复证据。
- 在文档与运行时证据中，策略更新可与机器人层可观测性、执行诊断清晰区分。

## 必须由人工决策、AI 不得自行捏造的关键节点

- 任何风险上调或实盘执行权限的扩张。
- 显著改变受支持实盘切片的策略切换或变更。
- 目标终止、归档，或对永久性外部阻塞的接受。
- 当自治策略中的受保护区域不再为 `none` 时，对受保护区域的修改。
