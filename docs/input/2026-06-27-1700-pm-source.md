### 问题3：其他策略是否也有类似问题？

其他策略的 bar\_freq 分析

| 策略                       | bar\_freq | is\_event\_driven |
| ------------------------ | --------- | ----------------- |
| listing\_fade (A)        | 1m        | True              |
| funding\_extreme (B)     | 1h        | False             |
| beta\_decouple (C)       | 1h        | False             |
| weekend\_wick (D)        | 1h        | False             |
| pre\_funding\_unwind (E) | 10m       | False             |
| pair\_mr (K)             | 1h        | False             |
| oi\_velocity (H)         | 5m        | False             |

AI结论：**所有非 event-driven 策略都存在同样的 exit klines 频率错配问题。**

- funding\_extreme (B)：3 bar × 1m = 3分钟，而非预期的 3小时
- beta\_decouple (C)：2 bar × 1m = 2分钟，而非预期的 2小时
- pre\_funding\_unwind (E)：3 bar × 1m = 3分钟，而非预期的 30分钟
- pair\_mr (K)：2 bar × 1m = 2分钟，而非预期的 2小时
- oi\_velocity (H)：2 bar × 1m = 2分钟，而非预期的 10分钟

只有 listing\_fade (A) 是正确的，因为它：

1. bar\_freq="1m"（与 exit klines 一致）
2. is\_event\_driven=True（event-driven 策略保持 1m exit 是正确的）

这意味着什么？

- 所有非 event-driven 策略的回测结果都是基于错误的持仓时间
- 实际持仓时间只有预期的 1/60（1小时策略）或 1/5（10分钟策略）
- 这会导致：
- 交易次数被高估（因为2分钟就出场，而不是2小时）
- 胜率被高估（短时间持仓更容易命中 TP）
- 风险被低估（短时间持仓暴露风险的时间更短）
- 整体表现被系统性高估

## 关键教训

1. Plan 文档必须覆盖"端到端"链路
   Plan 不能只覆盖策略逻辑，还必须覆盖：

1. Review 必须覆盖 Plan 没有覆盖的"灰色地带"
   Review 不能只做"Plan 说了什么"，还必须做"Plan 没有说什么"：

- Plan 没有覆盖 bar\_freq 与 exit klines 的对齐 → Review 必须补上

1. 系统性错误比单个错误更危险
   这不是 weekend\_wick 单个策略的问题，而是所有非 event-driven 策略的系统性错误。
   这意味着：

- 所有非 event-driven 策略的回测结果都不可信
- 需要重新回测所有策略
- 需要重新评估所有策略的表现
