## 背景

经过 [`docs/input/2026-06-27-1700-pm-source.md`](../input/2026-06-27-1700-pm-source.md) 中记录的修正（回测引擎 exit klines 频率错配 bug 修复）之后，重新跑出的回测结论位于 `reports/v3_output/` 下的 `v3_*.md` 报告中。

最新回测数据结论：**所有策略（A/B/C/D/E/K/H）均为 ABORT**，不允许推进到代码实现与 live。

这意味着 [`docs/plans/2026-06-25-1500-strategy-v3-zero-data-critical-strike.md`](../plans/2026-06-25-1500-strategy-v3-zero-data-critical-strike.md) 的计划可行性已被证伪，**V3.1 宣告死亡**。

### 2. V3.1 死亡的根因摘要

- 回测引擎存在系统性 bug：所有非 event-driven 策略的 exit klines 频率与策略 `bar_freq` 错配（统一用 1m 代替 1h/10m/5m），导致持仓时间被压缩到预期的 1/60 或 1/5，回测表现被系统性高估。
- 修复后重跑，所有 edge 的胜率、EV(R)、PF 均跌落至 ABORT 闸门之下。
- 详见上一份 PM 笔记的「关键教训」章节。

## 任务和要求

### 最终目标

挖掘出一套策略，满足以下全部条件：

1. 可被回测通过（通过单 edge 闸门与 ensemble 闸门）。
2. 可推进到 live 实盘。
3. 资金目标：**$10 → $50**。
4. 最大回撤不超过 **35%**。

### 工程化要求

通过搭建一套**流程循环**，工程化自动 edge 挖掘、搭建出具体 live 策略。

> 即：不是手工逐条 edge 试错，而是把「候选 edge 生成 → 回测 → 闸门判定 → 晋级/淘汰 → live 候选」沉淀为可复用的自动化流程。

### 硬约束

不能违背 [`docs/architecture/strategy-and-factor-constraints.md`](../architecture/strategy-and-factor-constraints.md) 中的约束吸引子，包括但不限于：

- 禁止传统技术指标（RSI、MACD、KDJ、MA、EMA、Bollinger Bands、ADX 等）作为核心 Alpha 来源。
- 禁止传统交易策略（传统趋势跟踪、传统均值回归、传统动量、传统配对交易）。
- 网络延迟 200-400ms，策略必须延迟无关或延迟容忍（信号尺度 ≥ 1 分钟）。
- 数据频率约束：K 线最大 1 分钟，订单簿/成交/清算实时 WebSocket。
- 仓位管理：单笔风险 ≤ 20% 权益；杠杆 10-15x；优先 post-only limit。
- 防过拟合：必须通过 IS/CPCV/WFA/OOS 验证协议。
- 数据零成本（沿用 V3.1 硬约束）：OKX + Binance 免费公共 API，禁止 Coinglass / Tardis 等付费源。
