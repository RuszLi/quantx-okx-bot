# 原始资料处理指南

## 用途

本指南说明原始素材在被固化为需求之前应当如何处理。

## 规则

当原始资料同时混入了以下内容时，不要直接让 AI 基于整份原始输入写代码：

- 业务目标
- UI 示例
- 实现层面的猜测
- 缺失的假设
- 尚未收敛的范围

## 推荐流程

1. 将原始素材存入 `docs/input/`。
2. 标注来源类型：产品/需求记录、原型稿、卡片组、第三方文章、抓取的行情或 K 线样本，或混合来源。
3. 把未解的问题写入 `docs/discussions/`。
4. 把综合后的结果写入 `docs/requirements/`。

## 有用的来源分类

- `source-pm-*.md` — 产品/需求原始记录
- `source-prototype-*.md` — 原型稿解读
- `source-cardset-*.md` — 卡片组或结构化需求文档
- `source-article-*.md` — 外部文章或参考资料
- `source-marketdata-*.md` — 抓取或导出的行情、K 线、订单簿、成交样本
- `source-research-*.md` — 第三方研究片段（指标论文、研报、API 文档摘录）

## 风险提示

结构化程度较高的素材仍有价值，但仍可能回答不了：

- 当前迭代的实际范围边界
- 业务决策所依赖的领域判断
- 哪些交互是核心、哪些是可选
- 原型是否完整到足以直接开发

对算法/因子研究类素材，还需额外警惕：

- 样本是否覆盖不同市场状态（趋势/震荡/高波动）
- 是否存在前视偏差（future leak）或幸存者偏差
- 假设是否依赖不可复现的数据源
- 样本量是否足以支撑结论（避免对短窗口过拟合）

## 文件头约定

本目录下每个输入文件的开头都应包含如下文件头：

    status: new | supplement | supersedes <filename>
    processed: pending | partial | done

- `status` 描述该文件相对其他输入的关系：
  - `new` — 独立的新输入，不会替代任何已有文件
  - `supplement` — 为已有输入补充额外上下文
  - `supersedes <filename>` — 替代某份既有输入文件，被替代的文件已失效
- `processed` 跟踪本输入是否被消费过：
  - `pending` — 尚未处理，AI 应当主动拾起
  - `partial` — 部分问题已澄清，但仍存在未解项
  - `done` — 已完整转入需求或讨论，AI 可跳过该文件

若人工放入的文件缺少该文件头，AI 应当：

1. 阅读文件内容。
2. 根据内容与上下文推断状态。
3. 补上推断的文件头，并注明由 AI 推断。
4. 继续后续处理。
