# Skill 索引

将此目录用于可复用的提示词和工作流程手册。

这些不是一次性的聊天消息，而是可复用的仓库记忆。

技能应主要捕获可复用的工作方法、审查方法或审计方法。不要将技能用作需求真相、设计真相或架构真相的替代品。

技能库不是吸引子。如果不通过 `AGENTS.md`、`docs/index.md`、活跃需求和所有者文档进行路由，大型技能库通常会退化为结构化的氛围编码。

这些提示词是复制项目的通用默认值。复制模板后，您必须根据项目的真实所有者文档、受保护区域、验证栈、命名约定、已知故障模式和误报容忍度对其进行定制。

## Skill 路由规则

选择技能前：

1. 首先阅读相关需求文档和所有者文档。
2. 使用 `AGENTS.md` 对任务类型进行分类。
3. 根据工作方法而非仅业务标签来选择技能。
4. 如果多个技能都适用，请在实施前请独立的子代理或审查员进行选择。
5. 如果没有现有技能明确适用，记录 `Skill: none` 并按正常的文档驱动流程继续。
6. 对于非琐碎的方案，在方案中记录技能选择依据和审查结果。

不要将广泛的业务场景技能作为项目特定所有者文档的替代品。如果某个场景频繁重复，首先检查是否缺少路由、所有者文档或方案指导。只有当可复用的工作方法稳定后，才将其提升为技能。

## 与工具原生技能的关系

`docs/skills/` 存放的是方法和审计类型的技能，它们位于仓库内部，可在不同工具和编辑器之间保持可移植性。一些 AI 工具也支持加载其原生的技能（例如工具自动加载的项目本地技能目录）。两者是互补关系，而非竞争关系：

- 将可复用的审查/审计方法和提示词放在 `docs/skills/` 中，以便与文档一起进行版本控制，并可供任何代理或人工阅读
- 如果你使用特定工具，可将工具加载的操作型技能（框架特定的操作指南、代码生成配方、调试配方）放在该工具自身的约定目录中
- 无论技能实际存放在何处，都应通过 `AGENTS.md`、`docs/index.md` 和所有者文档进行路由；技能选择的是工作方法，不能替代所有者文档的路由功能

本模板本身保持工具中立，不假定使用任何特定的 AI 工具。
